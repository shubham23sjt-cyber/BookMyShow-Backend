## Overview

**BookMyShow Backend** is a high-performance, modular NestJS application designed to emulate core ticket booking features. It handles the complete lifecycle of event discovery, venue scheduling, ticket availability, real-time seat locking (seat holds), checkout/booking transactions, and analytical tracking.

---

## Key Features

<CardGroup cols={2}>
  <Card title="User Management & Auth" icon="shield-halved">
    Role-based access control (RBAC) separating `USER` and `ADMIN` privileges with secure JWT verification.
  </Card>
  <Card title="Show Scheduling" icon="calendar-days">
    Easily bind movies/events to physical venues with specific dates, times, and scheduling conflict protection.
  </Card>
  <Card title="Dynamic Seat Allocation" icon="chair">
    Create and configure seat maps (VIP, Premium, Standard counts and prices) individually per show.
  </Card>
  <Card title="Temporal Seat Holds" icon="clock">
    Prevents double-booking via an atomic, transactional 10-minute temporary seat-locking mechanism.
  </Card>
  <Card title="Secure Bookings" icon="ticket">
    Processes ticket checkout within database transactions, automatically clearing holds upon successful booking.
  </Card>
  <Card title="Analytics Dashboard" icon="chart-line">
    Insights for admins, showcasing event revenue aggregates and real-time show occupancy percentages.
  </Card>
</CardGroup>

## Tech Stack

The service is constructed using the following core technologies:

*   **Framework**: [NestJS](https://nestjs.com/) (Node.js) - structured, modular framework.
*   **Database ORM**: [Prisma ORM](https://www.prisma.io/) - type-safe database queries.
*   **Database**: [PostgreSQL](https://www.postgresql.org/) - reliable relational database.
*   **Authentication**: [Passport.js](http://www.passportjs.org/) & [JWT](https://jwt.io/) - secure stateless auth.
*   **Containerization**: [Docker](https://www.docker.com/) & Docker Compose - easy deployment and development environment setup.

## Quick Start (Local Setup)

To spin up the server locally on your machine, follow these sequential steps:

<Steps>
  <Step title="Configure the Environment" icon="gears">
    Create a `.env` file in the root of the project with your PostgreSQL connection URL:
    ```env
    DATABASE_URL="postgresql://admin:password123@localhost:5432/bookmyshow?schema=public"
    PORT=3001
    ```
  </Step>

  <Step title="Start PostgreSQL" icon="database">
    If you use Docker, spin up the database container:
    ```bash
    docker-compose up -d postgres_db
    ```
  </Step>

  <Step title="Install Dependencies" icon="download">
    Pull down the project package assets:
    ```bash
    npm install
    ```
  </Step>

  <Step title="Run Database Migrations" icon="code-branch">
    Synchronize your database schema with the Prisma definition:
    ```bash
    npx prisma migrate dev
    ```
  </Step>

  <Step title="Start the Server" icon="play">
    Launch the NestJS application in development watch mode:
    ```bash
    npm run start:dev
    ```
    The server will start listening at `http://localhost:3001`. You can inspect the application routes via the REST client test suite at `api_testing.http`.
  </Step>
</Steps>
